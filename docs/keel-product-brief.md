# 产品构想文档（会话交接稿）

> 用途：把本次讨论的完整结论沉淀下来，供在新会话中继续推进。
> 日期：2026-07-01
> 状态：早期构想，尚未开工。命名暂定 **Keel**（见文末）。

---

## 1. 一句话定位

一个连接开发者线上环境的 AI 系统：吃 bug + 文档 + 日志 → 复现 → 定位 → 改代码 → **跑起来用运行时证据证明修好了** → 再把改动翻译成人能快速理解的架构影响图。

**卖的不是"帮你改代码"，而是"带证据、可理解的修复"。**

一句话对外话术（草稿）：
> "别的 AI 给你一个 diff 让你自己担惊受怕；我们给你一个复现、一份运行时证据、一张架构影响图——你只需要点批准。"

---

## 2. 起点：真实痛点

- 现状：AI 编程工具很强，但 **AI 改得太快，人跟不上**。
- 关键澄清：跟不上的**不是语法**，而是**改动的语义和影响面**。AI 一口气改 15 个文件，人肉眼看 diff 要 20 分钟才能重建"它动了系统哪根筋"。目标是把这 20 分钟压到 20 秒，并用图呈现。
- 目标用户：**熟练工程师**（不是 vibe-coding 的新手）。熟手也跟不上了。因此产品要给的是"精确、影响面、注意力指引"，不是"教你看懂代码"。

## 3. 一个被否掉的方向（重要，避免走回头路）

最初设想加入**桌面视觉识别 + 语音识别**来"像人一样点界面讲解代码"。讨论后否掉：

- 界面↔代码的映射是**结构化、精确、免费**的（DOM + source map、React fiber、LSP 的定义跳转/引用/调用图）。用视觉去逆推一个本有确定答案的东西，精度更低、成本更高、还不稳定。
- 语音在程序员安静专注的场景里多数人打字比说话快，属于炫技但没人用。
- **保留的诉求**：给人讲解要有**图像形式**（否则理解依旧困难）——但这个图不是界面截图，而是"随 AI 改动实时变化的架构 diff 图"（见第 4 节）。

结论：不做视觉识别；"图像形式"用架构图来满足。

---

## 4. 核心技术资产 A：把 AI 的 diff 翻译成人能懂的架构变化

**核心思想：别让 LLM 看文本 diff 猜意思；先把改动结构化成图，再让 LLM 在结构化的图上做叙述和排序。** 这样准确、便宜、不幻觉。

五层流水线：

1. **文本 diff → 结构化 diff（去噪）**
   解析成 AST，做 AST 级别 diff（difftastic / gumtree 思路）。把"改了 15 文件 800 行"压成"其实只发生了 6 件结构上的事"。

2. **结构化 diff → 图的 delta（这才是"架构变化"）**
   后台维护一张**活的代码图**：节点 = 模块/类/函数，边 = import/调用/数据流/继承。改动前后各算一次图，diff 两张图。"架构变化"= 图的 delta：新增跨模块边（新依赖）、引入环（循环依赖）、跨越分层边界、下游可达集变大等。**图的 delta 天生可画，直接就是第 3 节要的"图像形式"。**

3. **意图对齐（最大壁垒）**
   坐进 AI agent 的循环里（MCP 层包住 / 拦截它的 plan 和 tool calls），拿到它**声明的意图**。把"声明的意图"和"实测的图 delta"对齐，可做两件杀手级的事：
   - 生成人话摘要（"AI 重构了登录，改用 TokenService"）。
   - **检测偏离**：AI 说只动登录，图 delta 却显示它顺手改了 BillingModule。**这个"AI 干了你没注意到的事"的瞬间就是整个产品存在的理由**，静态工具做不到（它不知道 AI 本来"打算"做什么）。

4. **影响面 / blast radius**
   图上做可达性查询：改动函数被谁调用、哪些测试覆盖、连到哪个前端组件。输出"波及这 3 个组件和这条数据流"。熟手要的是**该把注意力放哪**。

5. **注意力排序（secret sauce）**
   用 LLM，但输入是第 2/3/4 层已结构化的 delta，不是原始文本。做分类（行为变更/重构/新功能/契约变更）+ 按"人需投入的注意力"排序。

**成品面板示例（给人看的不是 diff，而是）：**
> 🔴 契约变更｜`AuthService.verify()` 签名 `(token)`→`(token, scope)`，影响 4 个调用点，其中 `PaymentGuard` **未更新**，疑似遗漏
> 🟡 重构｜登录迁移到 `TokenService`（符合 AI 声明意图 ✓）
> ⚪ 12 处 import 路径调整（自动跟随，无需关注）
> [架构图：新边高亮，PaymentGuard 那条边标红]

难点：
- 图的**增量构建**（每次编辑重算全量调用图太贵）；LSP 给符号和引用，但**数据流的边**（最值钱）LSP 给不了，得自研，动态语言尤其难。
- 语言覆盖逐个啃，别摊大饼。
- "什么算架构级"的**阈值模型**直接决定面板太吵还是漏报，是生死线。

## 5. 端到端产品形态

### 输入
1. 软件背景等文档
2. 可远程连接的软件网站 + 服务器 + 运行日志
3. 当前遇到的 bug

### 输出
1. AI 改好的代码
2. 修改验证的截图
3. 帮人快速理解 AI 行为的改动说明（= 第 4 节的资产）

### 三个输出的商业价值不对等（关键战略判断）
- **输出 1（改代码）= 红海**。Cursor/Devin/Claude Code/Copilot 都在卷，正快速商品化趋近免费。**别自研，直接调用现成编码 agent。**
- **输出 2（验证截图）= 被低估的金矿**。多数 AI 工具不闭环（生成完就祈祷）。谁能拿出"复现→改→重跑→运行时证据"，谁在卖**信任**。
- **输出 3（理解说明）= 差异点**（第 4 节）。

→ **产品真正卖的是"2. 可验证 + 3. 可理解"，代码是商品。**

### 输入里的杀手锏
"可远程连接的环境 + 运行日志"解锁了全链路最难最值钱的一环——**复现与验证**。这也是对 Cursor 们的护城河（它们活在 IDE 里，够不着运行时）。

### 端到端循环
```
1. Bug 摄入与复现   ← 心脏，最被低估，决定生死
2. 定位              ← 日志 + 第 4 节的代码图，缩小嫌疑
3. 生成修复          ← 用现成 agent，别自研
4. 验证              ← 重跑复现，截图/日志证明修好 + 回归不倒退
5. 理解层            ← 第 4 节五层流水线
```
第 1 步与第 4 步是同一件事的两端：能复现才能验证。**复现引擎是产品的心脏，不是改代码。**

## 6. 三盆冷水（风险，务必带进下一阶段）

1. **"截图证明修好了"比想象难十倍**：截图只证明"界面现在看起来对了"，不证明 bug 真修复、不证明无回归。底下必须有"可确定复现的 case 通过 + 回归套件不倒退"撑着。否则制造**虚假信任**，比不验证更糟。
2. **全自主修 bug 与初衷矛盾**：初衷是"帮人跟上 AI"，全自主又把人踢出循环。建议 **human-in-the-loop**，在关键闸口让人确认（"这样复现对吗""定位到这里同意吗""这是证据和理解报告，批准合入吗"）。**输出 3 的理解层恰好就是这些闸口的界面，是串起整个系统的骨架，而非附属品。**
3. **线上环境写权限 = 信任地狱**：企业第一问就是安全和权限边界。**几乎一定要在隔离/影子环境复现和验证，不碰生产。** 第一天就要设计。

---

## 7. 建议的 MVP 切法

- 选**一个语言栈**：TS/React（图信息最丰富；前端 bug 天然适合截图验证；顺带白送"前端界面↔代码"映射）。
- 选**一类窄 bug**：有明确复现路径的前端行为 bug。
- 输出 1 用现成编码 agent。
- **90% 精力砸在：复现引擎 + 验证闭环 + 理解报告。**

---

## 8. 命名

- 定位有两根主线：**掌控（帮人跟上/稳住 AI）** vs **证据（卖验证/可信）**。
- 候选：
  - **Keel（龙骨）** — 船高速航行时让它稳、不偏航。隐喻：AI 是飞奔的帆，Keel 是让人稳住方向的龙骨。**首选**——能装下修复+验证+理解全部三个输出，延展性好。
  - **Verdict（裁决）** — "每次修复附一份裁决"，锋利、专业、to B 搭；但易被理解成纯验证工具，天花板略低。
  - 其他：Tether、Helm（掌控向）；Attest、Vouch（证据向）；Lucid（理解向，但 AI 圈快被用烂）。
- 暂定 **Keel**。**待办**：定名前查 `.com`/`.dev` 域名和商标（Keel/Verdict 都是常见词，可能要加前后缀如 `keel.dev`、`getkeel`、`keelhq`）。

## 9. 待决问题 / 下一步（新会话从这里接）

优先级排序（讨论中押第 1 个先啃）：

1. **复现引擎**：怎么把"一个 bug 描述 + 日志 + 活环境"变成一个能确定复现、之后又能用来验证的 case？（心脏，建议最先）
2. **验证闭环**：截图之外，怎么给出真正可信的"修好了"证据（复现 case 通过 + 回归套件）？
3. **权限与隔离**：怎么安全连线上环境而不吓跑客户（隔离/影子环境方案）？
4. **意图拦截的产品形态**：从 Cursor/Claude Code 等现成工具里把 AI 意图拦出来——这决定产品是插件、MCP 中间层、还是包一层 agent。
5. 定名收敛 + 域名/商标核查。
