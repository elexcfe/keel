# 统一任务入口：衔接复现、修复和独立验收

关联 [Issue #11](https://github.com/elexcfe/keel/issues/11)。最小实现已完成，离线验证与提交状态见下方记录；Issue 保存整体状态。不启动付费实验，不改写 Pi 产物。

## 结果与范围

使用者通过同一任务入口知道做到哪、为什么停、剩余预算以及下一步；现有 make_bug、run_pi、run_scenario、repair、delivery 继续承担已有工作。入口负责协调和展示，不替 Pi 创建场景、报告、数据或修复，不新增 Agent/模型启动器/RPC 服务。

先固定与 [交付入口 #12](https://github.com/elexcfe/keel/issues/12) 共用的最小引用约定：任务、各阶段运行、参考运行、最终候选运行、报告和独立审核。已有记录是执行事实来源，新任务记录只保存跨阶段关联、授权预算和明确决定；索引失效要提示，不能维护两份互相矛盾的成功状态。

## 实施顺序

- [x] 核查 make_bug/run_pi/run_scenario/repair/delivery 的输入输出，固定最少子命令。至少覆盖创建或关联任务、查询状态、发起复现、登记准入、启动修复、登记独立验收；命令命名在实施时统一，不预先增加服务。
- [x] 复用现有生成与执行入口；准入未通过不能修复，交付核查只到待验收，验收者明确记录最终结论。Pi 在修复会话内自行检查和纠错，不新增每轮外层重跑。
- [x] 建立任务级预算关联：执行各段共用余额，独立验收另计；明确启动前配置、人工等待口径、用量未知和延迟回报。不同阶段或原会话续接的累计用量不得双计，不因重试重置预算。
- [x] 状态查询只读；重复启动/并发操作有保护；中断保留已有结果。反馈待处理时显示问题和下一步，不自动恢复会话或发起付费重试。
- [x] 与 #12 对接交付索引，显示未完成条件；更新使用说明和资料索引，完成离线验证后提交推送并同步 Issue。

## 检查方法

使用合成项目和假 Pi 验证完整基本路径：复现→显式准入→同会话修复失败后纠错→待验收→记录独立结论。覆盖未准入、断言被改、版本变化、预算耗尽/未知、重复操作、同 session 用量去重、中断后查询以及清理。确认工具退出不等于 accepted，查询不调用模型，原报告和原始证据不被覆盖。

本期保留复现准入和最终独立验收，必要时确认修改范围；不做自动合并、自动扩预算、通用会话恢复状态机、多 Agent 调度或新界面。可读的中断状态不等于自动恢复已经实现。

## 本轮实施与验证（2026-10-20）

- 共用 schema 1 引用约定与调用示例集中在 [使用说明](../script_tool/make_bug/README.md#统一任务与-markdown-交付入口)。task.json 只记录关联、授权和决定；既有运行记录仍是事实来源。
- task_flow.py 复用 run_pi、repair 和场景执行器；handoff.py 生成外层 Markdown 与源码快照差异。Pi 通过提示词维护 HANDOFF.json、环境命令和导览，开发者不补写真实产物。
- 复现/修复共用预算，独立验收另计。跨阶段 session/entry 去重，某段费用未知不当零；中断只保留记录并显式核对，不自动恢复。review-check 的独立重跑与 Pi 交付分开关联，避免要求已退出的 Pi 为外层重跑再次改报告。
- 离线测试使用假 Pi 与合成任务，覆盖同会话失败纠错、显式准入/验收、缺项、版本/轮次错配、目录移动重跑、预算、用量未知和记录保护。真实人员理解效果及真实 Pi 交付改善尚未验证。
- 限制：初始化前和绕过入口的外部调用不自动纳入账本；费用仍是模型会话估算软上限。审核决定依靠外层职责约定，不是同一操作系统账号下的安全隔离。没有自动续接或合并；未改动/运行已有 Actual 任务。
- 验证命令：`python3 -m unittest discover -s script_tool/make_bug/test -p 'test_*.py'`，150 项中 149 通过、1 项真实 FFmpeg 集成测试因环境缺工具跳过；新增任务流测试 10 项。`node script_tool/make_bug/test/test_command_timeout.mjs` 策略测试通过，Markdown 链接/围栏与 diff 格式检查通过。
- 提交和 GitHub 交付状态以关联 Issue 的提交链接为准，未合入前不关闭 Issue。
