# 统一任务入口：衔接复现、修复和独立验收

关联 [Issue #11](https://github.com/elexcfe/keel/issues/11)。本文是实施方案，尚未开始实现；Issue 保存整体状态。本轮只整理近期主线和后续事项，不启动付费实验，不改写 Pi 产物。

## 结果与范围

使用者通过同一任务入口知道做到哪、为什么停、剩余预算以及下一步；现有 make_bug、run_pi、run_scenario、repair、delivery 继续承担已有工作。入口负责协调和展示，不替 Pi 创建场景、报告、数据或修复，不新增 Agent/模型启动器/RPC 服务。

先固定与 [交付入口 #12](https://github.com/elexcfe/keel/issues/12) 共用的最小引用约定：任务、各阶段运行、参考运行、最终候选运行、报告和独立审核。已有记录是执行事实来源，新任务记录只保存跨阶段关联、授权预算和明确决定；索引失效要提示，不能维护两份互相矛盾的成功状态。

## 实施顺序

- [ ] 核查 make_bug/run_pi/run_scenario/repair/delivery 的输入输出，固定最少子命令。至少覆盖创建或关联任务、查询状态、发起复现、登记准入、启动修复、登记独立验收；命令命名在实施时统一，不预先增加服务。
- [ ] 复用现有生成与执行入口；准入未通过不能修复，交付核查只到待验收，验收者明确记录最终结论。Pi 在修复会话内自行检查和纠错，不新增每轮外层重跑。
- [ ] 建立任务级预算关联：执行各段共用余额，独立验收另计；明确启动前配置、人工等待口径、用量未知和延迟回报。不同阶段或原会话续接的累计用量不得双计，不因重试重置预算。
- [ ] 状态查询只读；重复启动/并发操作有保护；中断保留已有结果。反馈待处理时显示问题和下一步，不自动恢复会话或发起付费重试。
- [ ] 与 #12 对接交付索引，显示未完成条件；更新使用说明和资料索引，完成离线验证后提交推送并同步 Issue。

## 检查方法

使用合成项目和假 Pi 验证完整基本路径：复现→显式准入→同会话修复失败后纠错→待验收→记录独立结论。覆盖未准入、断言被改、版本变化、预算耗尽/未知、重复操作、同 session 用量去重、中断后查询以及清理。确认工具退出不等于 accepted，查询不调用模型，原报告和原始证据不被覆盖。

本期保留复现准入和最终独立验收，必要时确认修改范围；不做自动合并、自动扩预算、通用会话恢复状态机、多 Agent 调度或新界面。可读的中断状态不等于自动恢复已经实现。
