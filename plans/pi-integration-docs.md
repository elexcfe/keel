## 关键决定

- Pi 是 Keel 当前的运行与编码主体；选择理由是核心精简、扩展入口完整，且仓库已经用它建立复现工作流。
- “稳定”记录为基于当前实际使用的选择理由，不写成未经长期数据证明的绝对结论。
- 复现与验证、定位与修复上下文、改动理解、流程与审核仍是四项业务职责，不要求一项对应一个 Pi 扩展。
- 第一阶段延续现有方式：文件化任务材料、启动脚本、固定复现包和独立验证入口。需要监听工具调用、增加交互或嵌入其他应用时，再依次评估 Pi 扩展、JSON/RPC 模式和 SDK。
- Keel 的检查与证据不能只存在于 Pi 会话中；固定检查、代码版本和结果文件仍由独立验证流程保存。
