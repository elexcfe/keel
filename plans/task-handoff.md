# 统一交付入口：环境、复现演示与修复说明

关联 [Issue #12](https://github.com/elexcfe/keel/issues/12)。本文是实施方案，尚未开始实现；Issue 保存整体状态。目标是让接手者从一个入口理解并重跑任务，优先采用 Markdown 和既有文件，不先做界面。

## 最小交付约定

| 内容 | 使用的既有材料 | 产出职责 |
| --- | --- | --- |
| 环境恢复与就绪条件 | dependencies.json、现有准备入口、scenario/env.sh/check.sh、测试数据与恢复说明 | Pi 明确具体条件与任务步骤；Keel 检查引用和可执行结果 |
| 复现演示 | 指定轮次的原视频/截图/日志、操作与观察导览 | Pi 随真实场景采集并说明；Keel 关联来源 |
| 修复与验证 | REPRO/FIX、实际 diff、前后运行编号、必要回归和外层审核 | Pi 写原因与改动说明；Keel 汇集事实；外层独立验收 |

依赖名称列表不能代替安装顺序、服务启动、数据准备和就绪检查；视频也不能代替精确版本与可复制命令。缺失项必须显式标出，不从报告文字猜测可执行步骤。原始问题、源码、场景、媒体与报告的任务/轮次关联复用现有记录。

## 实施顺序

- [ ] 与 [任务入口 #11](https://github.com/elexcfe/keel/issues/11) 先确认最小引用字段和缺失状态，避免一个目录一套命名。
- [ ] 明确 Pi 的交付要求：环境准备/检查命令、隔离测试数据及恢复方式、操作导览、原因和限制；尽量引用已有环境交接材料，不另维护冗余依赖清单。
- [ ] 生成只聚合事实与链接的 Markdown 交付入口，关联现有机器记录和 Pi 内容；不由 Keel 生成应属 Pi 的场景、环境命令、数据或分析。
- [ ] 将基础演示纳入交付：复杂 UI 操作展示关键准备、动作与结果；静态问题可用截图，非界面问题用日志/请求/数据。瞬间异常允许原视频为主，不强求截图恰好抓中；不要求逐帧校准、拼图或精美剪辑。
- [ ] 校验文件、任务/轮次、版本及必需条件；区分环境已检查、实际观察、自动检查与独立结论。定位不到视频时间或缺就绪证明时保留待核对，不编造精确结论。
- [ ] 完成合成任务的交付与重跑测试，更新使用说明和索引，提交推送后同步 Issue。

## 检查方法

用合成任务在新的临时目录按交付命令完成环境检查、数据准备和同一场景重跑；覆盖路径带空格、目录移动、原视频/报告缺失、轮次错配、源码已变、数据恢复缺失和部分完成。索引生成不得改写原始材料。离线样例只验证工具逻辑，不冒充 Pi 独立产物。

另做内容审查：接手者能找到“准备什么、怎样操作、异常是什么、改了哪里、如何验证、哪里没验证”。实际理解用时与准确率仍按 #8 另行测量；尚未测量就不声称节省审核时间。
