# 运行记录与独立任务

本次进程和会话由外部执行器记录。监测状态不代表 Bug 已复现，不修改或删除监测文件，不读取旧会话、其他任务或另一实验组的结果。修复任务可以读取本任务已验收参考运行及原复现报告。

使用 MAKE_BUG_PORT 建议的独立端口，先确认可用；实际使用的服务、端口和停止方法写入任务文件。只启动可在当前进程组内清理的服务，不通过 nohup、setsid 或后台守护进程逃离清理。不连接未知服务。

拆分任务的复现阶段先读取 environment/handoff.json、dependencies.json，按交接命令重启并检查环境。交接不完整时可以自行补齐，记录补装和原因，不把环境错误当成 Bug。

复现任务每完成一轮就用 write/edit 更新 result/REPRO.md；修复任务更新 result/FIX.md 并保留 REPRO.md。报告包含已执行步骤、业务观察、证据相对链接、重跑命令、未完成事项；未观察到目标异常也必须如实交付。不要删除失败轮次。
运行器为每阶段预留最多 600 秒（不超过阶段剩余时间的六分之一）收尾。进入收尾后 bash 被扩展阻止，之前的 bash 时限也不会越过收尾边界；用 read/edit/write 整理报告，不再安装、启动服务或探索新路线。环境阶段更新 environment/handoff.json。硬时限仍包含收尾，运行器始终保存交付缺失清单，文件齐全不代表验收成功。
禁止按名称或端口使用全局 pkill/killall 清理；服务必须由本次运行启动并保留父子关系。已有外部服务只借用，不关闭。独立场景使用 run_scenario.sh，公共运行器负责退出回收；浏览器正常结束时先关闭 context 以保存视频和 trace。
