# 环境准备与失败恢复

启动器会尝试准备依赖，但失败不会阻止你接手任务。先读 `result/logs/dependency-preparation.json`，不要把 pi 能启动或目录存在当作环境可用。

- `ready`：准备脚本正常退出，仍须检查项目能否实际运行；非 Node 项目也可能直接跳过准备。
- `failed`：先读 `result/logs/dependency-preparation.log`，再读其中指向的 `dependencies.log` 或构建日志，找真正导致退出的错误，不把 peer dependency 警告当作根因。
- `skipped`：用户跳过了自动准备，自行检查现有环境。

环境安装与诊断是当前任务的一部分。允许联网下载依赖，不允许搜索修复答案。先利用缓存完成必要修复，再执行 Bug 复现；不要直接让用户重复安装命令或重新生成项目。

## 自主判断依赖与跨 Issue 缓存

用户无需预先列出依赖，也无需逐项决定是否缓存。由你根据 BUG.md、项目清单与锁文件、本地安装说明、已有工具及实际运行错误，判断任务需要哪些依赖、兼容版本和安装位置。先检查再安装，不因缺少依赖清单停下来；只有确实缺少权限、凭据或关键材料时才报告阻塞。

本节替代旧 TASK.md 中“由准备者预装或决定是否共享”“不自动提升为共享工具”的规定。项目依赖缓存仍由 prepare_deps.py 管理，不手动改其内容。

- 先检查 `result/logs/tools.json`、`tools-config.json` 和实际共享目录；清单只是启动时快照，不保证完整或可运行。优先复用符合版本、平台、运行时要求的工具，使用前检查版本与实际启动。
- 项目锁定依赖留在 repo 内，由 `prepare_deps.py` 复用缓存。额外辅助工具不得改写项目清单或替代项目自身依赖。没有锁定版本的辅助工具，由你根据兼容要求选择精确版本并说明依据；必要时可查询包注册表的版本/引擎元数据，这属于依赖准备，不允许借机查修复答案。
- 自行判断缓存价值：通用测试工具、浏览器和下载成本较高且可重复使用的依赖，优先放到 `MAKE_BUG_SHARED_TOOLS`；只为本次 Issue 编写的脚本、修改过的包、不确定可迁移的安装目录放到 `MAKE_BUG_TASK_TOOLS`。无需逐项询问用户。
- 下载缓存和已安装工具分开判断。启动器已为 npm、pip、Playwright、Puppeteer 设置共享下载路径；即使只在本任务安装，也可以复用下载包。其他包管理器只在确认支持的缓存配置后接入共享 downloads 目录，不直接搬运虚拟环境或带绝对路径的安装产物。
- 需要独立 Playwright + Chromium 时，在任务目录直接运行 `python3 setup_tools.py --playwright-version <精确版本>`，脚本读取本任务 tools-config.json，按版本、平台、Node 隔离并加锁。无需交回准备者执行。项目已含匹配驱动时优先用项目安装器，保留共享浏览器环境变量。
- 其他通用工具可自行追加到共享目录，按工具名、精确版本、平台和必要的运行时版本区分。使用每个目标目录的文件锁，先在同一文件系统的临时目录安装并检查，再发布到尚不存在的版本目录；发布前确认产物不依赖临时绝对路径。不能安全迁移或并发发布时，保留任务独立安装，只复用下载缓存。失败或未验证的产物不能标成可复用。
- 已共享的安装目录只读使用，不覆盖、升级或删除其他任务需要的版本；新版本并存。缓存不是复现证据，不读取其他 Issue 的报告、测试或答案。浏览器 profile、凭据、合成测试数据、日志和构建输出保留在任务目录。
- 将依赖名称、精确版本、用途、实际路径、是否共享及原因、安装和运行检查结果写入 `result/logs/tool-decisions.json`（逐项记录），并在 REPRO.md 概述。安装完成后可运行 `python3 prepare_tools.py` 刷新已有工具清单；通用工具以实际目录及决策记录为准。下一次 Issue 仍要检查兼容性和运行状态，不能仅凭缓存目录存在跳过验证。

## 恢复步骤

1. 记录失败命令和根因。允许调整仅影响下载、工具路径或启动方式的配置；保留锁文件和业务代码，不随意升级依赖或关闭全部安装脚本。
2. 已失败且状态匹配的安装可以直接重新运行 `python3 prepare_deps.py`。旧任务没有状态记录、或者已改变安装模式时，在确认现有目录属于本次安装后运行 `python3 prepare_deps.py --retry`。Yarn 可继续链接和构建；npm ci 会重建依赖目录，不能删除用户业务改动。
3. **仅当 Issue 和启动路径明确是浏览器任务、故障仅在 Electron 二进制下载时**，可以运行 `python3 prepare_deps.py --profile browser --retry`。该命令记录模式、只跳过 Electron 二进制，其他构建仍执行。不要对桌面/Electron 问题这样处理，也不要宣称 Electron 可用。缺乏证据时维持 full 模式。
4. 再读 `result/logs/dependencies.json` 和实际执行输出，确认安装是否成功并尝试项目启动。启动器的 dependency-preparation.json 是你接手前的记录，不会随你修复自动改成成功；报告以最新实际证据为准。
5. 对同一个错误，仅在有新诊断或配置变化时重试。确实缺少权限、凭据、不可获得的资源，或无法在保持问题版本的前提下继续时，写 `result/REPRO.md` 的“阻塞”结论，附已尝试内容与最小解除条件。环境失败不算目标 Bug 已复现。

将环境调整、依赖模式、最终安装和启动结果写入报告。最终仍只复现、不修复业务代码。
